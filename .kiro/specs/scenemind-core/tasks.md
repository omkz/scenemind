# Implementation Plan: SceneMind Core

## Overview

Build the SceneMind core SDK in `packages/scenemind/` in TypeScript, following the design's four modules: `schemas.ts`, then `actions.ts`, then `runtime.ts`, then the public entry `index.ts`. Each step adds code that the next step uses. Tests import from the module files until the last step wires `src/index.ts`, after which public API and package checks run against the entry point.

The design handles concurrent `execute` calls by re-checking focus when a `focus` handler resolves (State Invariant 5). Keep that commit logic in one small helper in `runtime.ts` so it can later be swapped for a serialized-execute approach without touching the validation pipeline.

No `apps/`, React, Marzipano, LiveKit, or LLM code is part of this plan.

## Notes

- All tasks are required, including every test task (property tests, unit and example tests, type tests, and package checks). No task is optional.
- The package manager is pnpm. Use `pnpm install`, `pnpm test`, `pnpm run <script>`, and `pnpm exec <bin>` (for example `pnpm exec tsc --noEmit`, `pnpm exec vitest --run`).
- Property tests use fast-check inside Vitest with at least `{ numRuns: 100 }` and a tag comment such as `// Feature: scenemind-core, Property 5: Validation order matches the oracle`.
- Property tests 5.4–5.5, 7.4–7.10, and 9.1–9.3 depend on the generators and model from task 5.3.
- The focus re-check guard lives in one helper in `runtime.ts` (task 7.2) so it can be replaced by serialized `execute` calls later without changing validation.
- Requirement 2.4 is covered by the dependency check and review; Requirement 9.3 by review plus type tests.
